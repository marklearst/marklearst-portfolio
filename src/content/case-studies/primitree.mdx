<CaseStudySection title="From Figma Variables to build rules">
  <div className="space-y-6">
    <CaseStudyParagraph>
      A token system runs on rules about which layers hold raw values, which
      must use references, who owns each token, and which aliases a change
      touches. I built <strong>Primitree</strong> so those rules live in
      configuration a build can check, and keep holding as the system changes.
    </CaseStudyParagraph>

    <CaseStudyParagraph>
      It grew out of <strong>@figma-vars/hooks</strong>, which handled reading
      Figma Variables into React. Primitree adds the architecture checks,
      change reports, and generated output, split across six packages.

<CaseStudySection title="Configuration and change checks">
  <div className="space-y-6">
    <CaseStudyDetails summary="Configuration for four output formats">
    <CodeBlock
      language="typescript"
      analyticsLabel="primitree_layer_config"
      code={[
        "export default defineConfig({",
        "  schemaVersion: 1,",
        "  sources: {",
        "    brand: {",
        "      type: 'dtcg',",
        "      file: './tokens.json',",
        "      architecture: {",
        "        layers: [",
        "          // holds raw values",
        "          { id: 'base', roots: ['color'], values: 'literal' },",
        "          // must point at base, never hold a value",
        "          {",
        "            id: 'meaning',",
        "            roots: ['semantic'],",
        "            values: 'reference',",
        "            references: ['base'],",
        "          },",
        "        ],",
        "      },",
        "      ownership: { default: ['design-systems'] },",
        "      outputs: {",
        "        directory: './generated',",
        "        formats: ['dtcg', 'css', 'typescript', 'tailwind'],",
        "      },",
        "    },",
        "  },",
        "})",
      ].join('\n')}
    />
    </CaseStudyDetails>

    <CaseStudyMutedText>
      Figma-export diffs match tokens on their stable Figma IDs. Matching on
      names would turn every rename into an unrelated deletion and addition.
    </CaseStudyMutedText>

    <CaseStudyMutedText>
      For a configured DTCG source, the diff reports changed tokens, affected
      aliases, and policy findings.
    </CaseStudyMutedText>

    <CaseStudyMutedList className="space-y-2">
      <li>Renames, moves, removals, and type changes are classified as breaking</li>
      <li><code>--fail-on-breaking</code> exits with code 2 so CI can block on it</li>
      <li>Output as Markdown for review, or JSON for tooling</li>
    </CaseStudyMutedList>

    <CaseStudyMutedText>
      Running with <code>--check</code> reports missing, changed, and unexpected
      files without writing anything, and exits 1 on any difference. That's how
      CI confirms the committed tokens still match what the source produces.
    </CaseStudyMutedText>
  </div>
</CaseStudySection>

<CaseStudySection title="Generated files need an ownership record">
  <div className="space-y-6">
    <CaseStudyMutedText>
      Each configured DTCG build writes a manifest next to its output. The next
      build reads that manifest and won't overwrite a listed file whose hash
      has changed, or touch any path the manifest doesn't list. If someone
      hand-edits a generated file, the build stops with an error.
    </CaseStudyMutedText>

    <CaseStudyMutedText>
      Builds also stage their output before replacing anything, and keep
      recovery information if a run is interrupted.
    </CaseStudyMutedText>

    <CaseStudyMutedText>
      Output follows DTCG 2025.10. Aliases stay as token references (they
      aren't flattened to values), and Figma modes map to Resolver contexts. Anything
      Figma-specific that the spec has no place for goes into a namespaced
      extension.
    </CaseStudyMutedText>

    <CaseStudyMutedText>
      Figma IDs, scopes, and code syntax live under
      <code>$extensions['com.primitree']</code>. Booleans use a documented
      extension, since DTCG has no boolean type.
    </CaseStudyMutedText>

    <CaseStudyDetails summary="Output formats and file-safety checks">
    <CaseStudySubheading>Generated formats</CaseStudySubheading>

    <CaseStudyMutedText>The configured pipeline produces four output formats:</CaseStudyMutedText>

    <CaseStudyMutedList className="space-y-2">
      <li>DTCG 2025.10 token files plus a resolver document for contexts</li>
      <li>CSS custom properties, with contexts as selector axes</li>
      <li>Tailwind theme output</li>
      <li>Typed TypeScript token exports</li>
    </CaseStudyMutedList>

    <CaseStudySubheading>Transactional writes</CaseStudySubheading>

    <CaseStudyMutedList className="space-y-2">
      <li>Output staged before it replaces anything installed</li>
      <li>An interrupted run leaves its backup and cleanup sidecars in place, reports every retained path, and stops before writing over them</li>
      <li>The output directory must sit under the config directory and cannot contain the source file</li>
      <li>File identity is recorded before a read and compared after, so a path swapped mid-read gets rejected</li>
      <li>The output directory and its ancestors are rechecked during a scan, which stops if one changes underneath</li>
    </CaseStudyMutedList>

    <CaseStudySubheading>Input limits</CaseStudySubheading>

    <CaseStudyMutedText>
      There are caps on file sizes, token file counts, directory entries,
      nesting depth, path length in UTF-8 bytes, and path component counts
      after symlink resolution. Symbolic links and special files are rejected.
    </CaseStudyMutedText>
    </CaseStudyDetails>
  </div>
</CaseStudySection>

<CaseStudySection title="Six packages, still a prerelease">
  <div className="space-y-6">
    <CaseStudyParagraph>
      Primitree is on npm as <code>1.0.0-next.1</code>, a release candidate.
      I'm still settling the API before 1.0.
    </CaseStudyParagraph>

    <CaseStudyMutedText>
      A Figma plugin exports local variables for teams without Enterprise API
      access, so you don't need a particular Figma plan to start.
    </CaseStudyMutedText>

    <CaseStudyMutedText>
      All six packages are prereleases over a shared core, built with Turborepo
      on Node 24 and pnpm 11:
    </CaseStudyMutedText>

    <CaseStudyMutedList className="space-y-2">
      <li><code>primitree</code> for the unscoped CLI entry point</li>
      <li><code>@primitree/core</code> for normalization, the token graph, diffing, and API access</li>
      <li><code>@primitree/dtcg</code> for conversion and the CSS, Tailwind, and TypeScript emitters</li>
      <li><code>@primitree/cli</code> for check, build, inspect, diff, and scaffolding</li>
      <li><code>@primitree/hooks</code> for reading built tokens in React, or the live API with SWR</li>
      <li><code>@primitree/mcp</code> for serving the graph to MCP clients</li>
    </CaseStudyMutedList>

    <CaseStudyMutedText>
      The MCP server exposes the token graph through{' '}
      <code>list_collections</code>, <code>get_token</code>,{' '}
      <code>resolve_context</code>, <code>search_tokens</code>, and{' '}
      <code>diff_tokens</code>, so an agent can query tokens, resolve contexts,
      and diff changes.
    </CaseStudyMutedText>
  </div>
</CaseStudySection>
