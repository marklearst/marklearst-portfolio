<CaseStudySection title="When sign-off stops matching the design">
  <div className="space-y-6">
    <CaseStudyParagraph>
      I built and maintain <strong>a11y Companion</strong>, a widget for
      accessibility review in Figma and FigJam. Version 3.0.0 pairs The A11Y
      Project Checklist, 64 items in 16 sections, with canvas audits, contrast
      inspection, reviewer sign-off, and handoff records.
    </CaseStudyParagraph>

    <CaseStudyParagraph>
      The first version let teams complete the checklist in the design file.
      Once a section was signed, though, it couldn't tell anyone that changed
      items needed another look. In v3.0.0 a named reviewer's signature records
      item ids, completion state, and checklist revision. If any of that
      changes, the stamp turns amber and the section is marked for re-review.
    </CaseStudyParagraph>

  </div>
</CaseStudySection>

    <CaseStudyMutedText>
      The central decision was to make missing or outdated evidence impossible
      to mistake for readiness. The rest follow from it:
    </CaseStudyMutedText>

    <CaseStudyMutedList className="space-y-2">
      <li>
        Checklist sections collapse and show their own progress, so 64 items stay navigable
      </li>
      <li>
        Every item cites its WCAG criterion, because people trust a cited rule more than a tool's opinion
      </li>
      <li>
        Audits group repeated findings into causes and say what's kept and what's only a sample
      </li>
      <li>
        Light and dark themes with six accent colors change the widget and never the record
      </li>
    </CaseStudyMutedList>

    <CaseStudyMutedText>
      I also decided what to leave out. One renderer for Figma and React would
      hide their different host constraints. A cloud dashboard with accounts
      would pull the evidence away from the design. Unlimited synced audit
      history adds multiplayer weight and review noise. And a bounded scan of
      a design can't back up an automated compliance claim, so the widget
      never makes one.
    </CaseStudyMutedText>

<CaseStudySection title="What the Geist file exposed">
  <div className="space-y-6">
    <CaseStudyMutedText>
      Early token pairing matched on names containing "text" and "bg". Testing
      against Vercel's Geist file showed where that fell short. Ramp-named
      systems use <code>gray/100</code> through <code>gray/1000</code>, so the
      audit was only checking about twelve pairs. Now it infers role from the
      trailing numeric step. High steps read as ink and pair against low steps
      and explicit surfaces in the same family, and the pair cap went up to 800.
    </CaseStudyMutedText>

    <CaseStudySubheading>State has to survive the widget runtime</CaseStudySubheading>

    <CaseStudyMutedText>
      The widget runtime clears module memory between interactions, so Watch
      ownership has to live somewhere that survives the reset. A couple of
      other runtime quirks needed workarounds too.
    </CaseStudyMutedText>

    <CaseStudyMutedList className="space-y-2">
      <li>
        Watch ownership uses the durable <code>sessionId</code>
      </li>
      <li>
        Export and clipboard access run through a hidden iframe bridge, since the widget sandbox has neither
      </li>
      <li>
        Empty spacer AutoLayouts default to 100px tall, so an explicit <code>height=0</code> keeps them from inflating badge and chip rows
      </li>
    </CaseStudyMutedList>
  </div>
</CaseStudySection>

<CaseStudySection title="A review record the team can hand off">
  <div className="space-y-6">
    <CaseStudyMutedText>
      Native Dev Mode annotations keep findings attached to the affected
      layers, and Canvas Record gathers review progress and evidence in one
      Figma frame. Both have to hold up when someone runs the review again.
    </CaseStudyMutedText>

    <CaseStudyMutedList className="space-y-2">
      <li>
        Annotate writes Dev Mode annotations for the examples shown and says how many findings it left out
      </li>
      <li>
        Read-modify-write preserves existing annotations and stays idempotent on re-run
      </li>
      <li>
        Annotations link the relevant WCAG Understanding page and cite the properties that failed
      </li>
      <li>
        Canvas Record compiles progress, sign-offs, audit summaries, and priority findings into one Figma frame per page
      </li>
      <li>
        Re-running Record refreshes the same widget-owned frame and doesn't create duplicates
      </li>
      <li>
        The record reads Action required, Review required, In progress, or Ready for handoff, and a partial or selection-only scan can't reach Ready
      </li>
      <li>
        The record keeps one canonical palette, whatever theme each reviewer's widget uses
      </li>
    </CaseStudyMutedList>

    <CaseStudyMutedText>
      Exports come in six formats: Markdown, CSV, JSON, SVG, PDF, and plain
      text for the clipboard, all built from the same page data as the Canvas
      Record. The Markdown, CSV, and JSON reports carry run owner and time,
      scope, full counts, grouped evidence, and a note whenever the rows are
      only a representative sample.
    </CaseStudyMutedText>

    <CaseStudyParagraph>
      Today the widget has 450+ users on Figma Community and runs in twenty
      locales.
    </CaseStudyParagraph>

<CaseStudySection title="One contract, every output">
  <div className="space-y-6">
    <CaseStudyMutedText>
      The widget, the product site's demo, the Canvas Record, the exports, and
      the release checks all read the same typed accessibility state from one
      contracts package. Each one renders that state natively. Figma and React
      keep their own renderers and share only the rules, because the Widget
      API and the DOM have different primitives.
    </CaseStudyMutedText>
