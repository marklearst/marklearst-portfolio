<CaseStudySection title="Implementation Decisions">
  <div className="space-y-6">
    <CaseStudySubheading className="mt-0">Declare Actions in Configuration</CaseStudySubheading>
    <CaseStudyMutedText>
      I put each action's icon, label, tooltip, and variant in a shared
      configuration. Controls read that configuration to render mission actions:
    </CaseStudyMutedText>

<CodeBlock
  language="typescript"
  analyticsLabel="action_configs"
  code={`// AutonomyWidget.configs.ts
const ACTION_CONFIGS = {
  pause: {
    icon: PauseIcon,
    label: 'Pause',
    tooltip: 'Pause current mission',
    variant: 'secondary'
  },
  orbit: {
    icon: OrbitIcon,
    label: 'Orbit',
    tooltip: 'Enable orbit mode',
    variant: 'primary'
  },
  // ... 15+ mission actions
} as const

// Usage: Automatic UI generation
<IconButton {...ACTION_CONFIGS[action]} />`}
/>

    <CaseStudySubheading>Separate Mission State from Controls</CaseStudySubheading>
    <CaseStudyMutedText>
      A React Context provider manages mission type, timer, and action states.
      Remote state synchronization, event subscription hooks for analytics
      telemetry, and runtime config injection connect the widget to the
      surrounding application.
    </CaseStudyMutedText>
    <CaseStudyMutedText>The component system includes:</CaseStudyMutedText>
    <CaseStudyMutedList className="space-y-2">
      <li><strong>Dynamic Timer:</strong> Circular countdown ring with animated icon transitions</li>
      <li><strong>OrbitSlider:</strong> Dual progress indicators with chevron controls</li>
      <li><strong>IconButton:</strong> Shared component with icons, tooltips, and labels</li>
      <li><strong>StatusMessage:</strong> Expandable area for mission updates</li>
      <li><strong>Tooltip System:</strong> Custom tooltips with ARIA support</li>
    </CaseStudyMutedList>

    <CaseStudySubheading>Make Component States Reviewable</CaseStudySubheading>
