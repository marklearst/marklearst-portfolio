<CaseStudySection title="Keep brand differences in the token layer">
  <div className="space-y-6">
    <CaseStudyMutedText>
      With the token-based theming I built, 60% of components are shared across
      all 4 brands. The other 40% are customized per brand through token
      overrides. A brand team imports the shared Aurora components, swaps in its
      own colors, typography, and spacing through tokens, and extends a
      component only when it needs behavior the other brands don't.
    </CaseStudyMutedText>

    <CaseStudyMutedText>
      The React and React Native components share their core logic, and
      adapters handle the platform-specific rendering.
    </CaseStudyMutedText>

    <CaseStudySubheading>The token pipeline</CaseStudySubheading>
    <CaseStudyMutedText>
      I built the pipelines that synced tokens from Figma Variables through
      Style Dictionary into the React and React Native codebases, which cut the
      manual Figma-to-code handoffs for all four brands. My governance document
      sets the naming, modes, and approval rules for changing a token. Tokens
      are layered (primitive -> semantic -> component), and the brand themes
      are built on that structure. The tokens started in Tokens Studio, and I
      later migrated them to native Figma Variables on Figma Enterprise.
    </CaseStudyMutedText>

    <CaseStudySubheading>Accessibility in component review</CaseStudySubheading>
    <CaseStudyMutedText>
      The target was WCAG 2.1 AA, written into the design-to-code workflow,
      and I closed 80+ accessibility defects along the way. Component reviews
      covered:
    </CaseStudyMutedText>
    <CaseStudyMutedList className="space-y-2">
      <li>
        ARIA patterns and semantic HTML
      </li>
      <li>
        Keyboard navigation and focus management
      </li>
      <li>
        Screen reader testing with NVDA and JAWS
      </li>
      <li>
        Color contrast checks (4.5:1 minimum for text)
      </li>
      <li>
        Automated accessibility checks in CI/CD
      </li>
    </CaseStudyMutedList>

    <CaseStudyMutedText>
      I documented each component's variants, states, and accessibility
      behavior in Storybook, so everyone reviewing a component, from design to
      QA, was looking at the same build.
    </CaseStudyMutedText>

  </div>
</CaseStudySection>
