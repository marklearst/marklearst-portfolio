<CaseStudySection title="Keep brand differences in the token layer">
  <div className="space-y-6">
    <CaseStudyMutedText>
      I built a token-based theming system that allowed 60% of components to be
      shared across all 4 brands, while the remaining 40% could be customized
      per brand through token overrides. Teams could:
    </CaseStudyMutedText>
    <CaseStudyMutedList className="space-y-2">
      <li>Import shared Aurora components</li>
      <li>Apply brand-specific themes via token swaps (colors, typography, spacing)</li>
      <li>Extend components only when brand-specific behavior was needed</li>
    </CaseStudyMutedList>

    <CaseStudyMutedText>
      React and React Native components shared core logic, with adapters
      handling platform-specific rendering.
    </CaseStudyMutedText>

    <CaseStudySubheading>From governance to generated code</CaseStudySubheading>
    <CaseStudyMutedText>
      I designed and built automated workflows that synced design tokens
      from Figma Variables through Style Dictionary into React and React Native
      codebases, removing manual handoff steps between design and development.
      Naming conventions, modes, and approval rules defined how teams organized
      and changed tokens. A semantic token structure (primitive -> semantic ->
      component tokens) supported brand-specific themes.
    </CaseStudyMutedText>

    <CaseStudySubheading>Accessibility in component review</CaseStudySubheading>
    <CaseStudyMutedText>
      WCAG 2.1 AA was the accessibility target. Component work included:
    </CaseStudyMutedText>
    <CaseStudyMutedList className="space-y-2">
      <li>ARIA patterns and semantic HTML</li>
      <li>Keyboard navigation and focus management</li>
      <li>Screen reader testing with NVDA and JAWS</li>
      <li>Color contrast validation (4.5:1 minimum for text)</li>
      <li>Automated accessibility testing in CI/CD pipeline</li>
    </CaseStudyMutedList>

    <CaseStudyMutedText>
      I built Storybook documentation for component variants, states, and
      accessibility features so designers, developers, and QA could review the
      same implementations.
    </CaseStudyMutedText>

  </div>
</CaseStudySection>
